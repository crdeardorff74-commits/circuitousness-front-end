## 2026-05-16 — SFX system + click + broken-path flash/fade

- **`audio.js` added**. Per-type shuffle bag (Fisher-Yates, no variant repeats inside a type until exhausted); OR-triggers pick the type uniformly first, then a variant from that type's bag. Single `play()`, `playLoop(key, spec)` / `stopLoop(key)` for the overlap glitch. **Glitch overlap = single variant looped via `Audio.loop`**, NOT a chain through the pool — earlier rotating-chain implementation was wrong per the user. 200ms duck/fade-out on every `play()` so a new sound supersedes anything still playing; the natural `ended` event is processed BEFORE the chain-handoff for loop variants so loop hand-offs don't fade themselves. `click()` synthesized via Web Audio (lazy AudioContext, ~30ms filtered-noise burst with frequency jitter); bypasses ducking pipeline; fires on tile rotations + hint. SFX skipped during replay.
- **Eager preload at module init** — without explicit `audio.load()` even `preload='auto'` is ignored by mobile browsers. ~85 parallel fetches at page load with `PRELOAD_FIRST = ['cinematic_bass', 'applause_long']` priority because those fire first in any session. Bandwidth spike at page load is the trade. **iOS/iPad Safari WILL FAIL** to load — GitHub 302 redirects don't follow in Audio elements (same problem TANTЯO solved via backend proxy). Mirror via backend if iOS support matters.
- **Twin-twist-break SFX rule** (game.js handlePointer). Per-path analysis. A = clicked tile / quad in quad mode; B = partner tile / partner quad (`_twin.partner`). Fire iff: (1) A NOT in lost (player didn't directly break their tile — that's "their choice"), AND (2) `bOldLaneGone` — any pre-walk port-pair through B's cells is missing in post. This is **strictly broader than "B's cell in lost"**: catches the elbow-still-lit case where B's cell stays lit via a different corner but its old chain-corner is gone, orphaning everything past B. AND (3) remainder (lost ∖ bCells) spans ≥ 2 "units" — cells in singular, quads in quad — so single-tile tip-loss doesn't fire.
- **Broken-path visual** = `Render.fadeLanes(entries)` Pass D after lit pass: 200ms FLASH (additive composite via `globalCompositeOperation='lighter'`, overlay alpha 0.7→0) then 1500ms alpha ramp 1→0. Lane entries captured pre-rotation; safe to redraw because A+B are excluded from the fade set (their rotations changed), all other lost cells kept the same tile rotation so the lit-lane geometry is still valid. Cleared on newPuzzle. partial-draw rotation animation is disabled while any fade is alive (palettes vary per frame).
- **Joined-paths flash** (two paths share a lane) — `JOINED_PATH_IDX = -2` sentinel in `buildLitKeys`; `litPalette(-2)` returns time-modulated dark red (450ms period would have been too fast; 900ms reads correctly). Old behavior of overwriting one path's color with another's was confusing.

## 2026-05-01 — Partial-redraw during rotation animation

- Old `draw()` iterated all ROWS×COLS tiles in three passes (dim channel, lit channel, walls) every frame, regardless of how few tiles were actually animating. On 15×15 a full draw measured ~31ms — below 60 fps and visibly choppy.
- Refactored: extracted body to `drawCore()` (full draw, used for initial loads, hint pulses, dramatic flash, resize, and the first frame after a rotation kick-off). Added `drawAnimatedFrame()` that only re-renders animating tiles + their 8 neighbors, clipped to the bounding box (with `0.3*cellSize` margin for the 45°-rotation overshoot). Hoisted `buildLitKeys`, `renderTileDim/Lit/Wall`, `laneIsOpposite`, `laneIsVertical` so both paths share them.
- `animateRotationAt` sets a `needsFullDraw` flag so the FIRST frame after a rotation kick-off is a `drawCore` (the canvas still showed PRE-rotate state, so the partial-redraw region needs a fresh backdrop). Subsequent frames during the same animation use `drawAnimatedFrame`.
- `draw()` falls back to `drawCore` whenever a hint pulse, dramatic flash, or pulse-driving state is active (those vary palettes globally each frame). Rotation-only animations get the fast path.
- Clip path is the **union of dirty cell rects**, not their bounding box. **Why:** twin-pair rotations have two animating tiles that can be far apart on the grid. A bbox-clip would clear the entire gap between them, and since `drawAnimatedFrame` only redraws the dirty cells (not the gap), the body bg would show through the canvas as a transparent void. Per-cell clipping leaves non-dirty cells intact.
- Measured on 15×15: drawCore = 31.6ms, partial draw ≈ 1.9ms. Still well under the 16ms 60fps budget.

## 2026-05-01 — Per-side overlap-interval clustering for path rings

- `drawCircuitOutline` previously treated each perimeter side as a single shared resource: any pair whose route touched that side bumped everyone else's rank, even if the routes occupied disjoint segments. With 4 paths this routinely pushed an "alone on its segment" path several rings outward for no visual reason.
- Fix: `computePathRoute` now returns `sideSpans` — perimeter-coord intervals per side that the route actually covers. `drawCircuitOutline` builds one cluster per maximal-overlap group of intervals on each side (sort by lo, merge while next.lo ≤ curHi). `offsetFor(pairIdx, side)` uses the *cluster* size + rank instead of the side-wide usage list. Disjoint intervals on the same side both get baseLen now.
- Min path length floor `MIN_PATH_CELLS = 4` enforced in path 1's loop, `tryAddPath`, and the backtracking `place` (lane count for `pathIdx` must be ≥ 4 to accept a candidate). Tiny entry-near-exit stubs are rejected.

## 2026-05-01 — 4th path (orange) wired in + backtracking placement

- **4-path mode added**: slider max bumped to 4. Plumbing: `entry4`/`exit4` state in maze.js, `setPathCount` accepts 4, snapshot/restoreState/loadSnapshot carry the new fields, `updateHighlighted` walks/tags it as `pathIdx=3`, public API exposes `entry4`/`exit4`. game.js `setPathCount` validation extended.
- **Orange palette**: `LIT_ORANGE = '#FFA040'` (HI `#ffd6a8`, LO `#7a3a05`) in render.js. `litPalette(3)` returns it. `drawCircuitOutline` `pairs` array pushes `{ entry4, exit4, pathIdx: 3 }` when present. `padFracFor(4) = 1.15` (extra room for a 4th perimeter ring). `pathsWon` now `[false×4]`.
- **Backtracking placement for 4-path mode** (the linear placement boxed path 4 out almost every time): `buildPuzzle` branches on `pathCount === 4` into a recursive `place(currentLanes, pathIdx, used)` that tries `MAX_BT_PAIRS=3` endpoint configs × `MAX_BT_ROUTES=5` DFS routes per level, capped by a shared `budget.steps=100` total `generateLanes` calls. On success returns the all-4-paths lane map; on budget exhaustion falls back to the deepest partial via a `snap()` snapshot that records best.depth + the entry/exit pairs at that depth. **Why:** greedy DFS for paths 2/3 picks routes that disconnect path-4-feasible regions; backtracking rolls back a path and tries a different (pair, route) when a deeper level fails. Outer init `maxAttempts` for 4-path mode dropped to 25 (was 80) since each attempt is now thorough.
- **Verified empirically**: 6/6 4-path builds succeeded on 8×8 in ~20s total; 12×12 also reliably places 4 paths.
- **Tried + reverted earlier**: scaling `tryAddPath` retries by `pathIdx` (12 + pathIdx*6) ballooned per-init cost beyond 30s. Reverted to flat MAX_PATH_GEN_TRIES=12 before adding backtracking.

- **Quad twins** (whole-quad pairing in quad mode): `assignQuadTwins` pairs entire 2×2 quads via `TWIN_COLORS`. Each sub-tile in a paired quad gets `_twin = { partner: "qr*2,qc*2", color }` referencing the partner quad's TL. `scrambleQuads` scrambles twin pairs with the SAME turn count (otherwise lockstep can never bring both to scramble=0 simultaneously). `Maze.rotate`/`applyHintAt`/`hint` quad branches all cascade to the partner quad. `flashTwinPair` in quad mode adds all 8 sub-tiles (4 per quad) to `dramaticPulseTiles` so the WHOLE quad flashes, not just the clicked sub-tile.
- **Hint port-equivalence fix**: `tileShouldSkip` uses `rotationsHaveSamePorts(type, current, solution)` instead of strict `rotation === _solution`. **Why:** STRAIGHT tiles are 2-symmetric — rotations 0/2 and 1/3 expose identical port sets, so a tile at rotation 2 with solution 0 is *visually* correct and the player would rightly object to it being hinted. Cross is 4-symmetric (always correct), elbow has no symmetry (strict equality).
- **Hint twin-pair conservative skip**: skip the pair (both members) if *either* tile in the pair has `tileShouldSkip = true`. **Why:** lockstep rotation means hinting one disturbs the partner. If the partner was at solution, the hint moves it AND locks it — leaving it at the wrong rotation, locked, making the puzzle unwinnable. Skip the whole pair instead. Same logic in quad mode at the quad level.
- **`effectivePalette` layer ordering**: `_playerLocked` palette override must run BEFORE the dramatic-pulse blend, otherwise the white player-lock palette overwrites the pulse blend every frame and the flash becomes invisible. Order: twin/hint base → hint pulse → **player-lock white** → dramatic pulse → return.
- **Hint rotation animates**: `applyHintAt` returns `{ turns }`, `hint()` propagates it, `Render.animateRotationAt(r, c, ccw, turns)` accepts an N-turn count and computes `deltaRad = (±π/2) * turns`. Replay's hint branch also passes turns. Duration stays constant at 200ms regardless of turns — a 270° spin in 200ms feels fine; could tune later if it reads as rushed.

## 2026-04-30 — 2-path canonical check + animation default

- **2-path mode now runs the canonical check** (per-path BFS-shortest with the OTHER path's exclusive cells blocked must be ≥ intended length, plus rotation-cost shortcut detection). 3-path stays at "first valid build wins" — adding canonical on top would compound the already-tight retry budget. **Why:** the prior "shortcuts are unlikely with multi-path density" rationale is probabilistic, not a proof, and breaks down on sparse 2-path puzzles.
- **"Shortcut" definition for 2-path**: alternate paths that don't traverse cells exclusively on the OTHER path. Shared cross tiles (lanes from both paths) are NOT blocked — each path is entitled to its own lane through the cross. The user explicitly chose this simplification over a joint-path canonical (which would also have to verify the alt leaves the other path solvable).
- **Cost**: 2-path canonical generation is ~10s on 8×8, ~18s on 10×10 in the dev preview. Pre-gen worker absorbs this off-thread; lookahead cache normally hides it from the player. **Tunable knobs:** `maxAttempts = 24` (outer retry) and `smart < 6` (smartReroll iterations per attempt) in the `pathCount === 2` branch of `init()`.
- **8×8 2-path is on the edge** — sometimes succeeds, sometimes the smartReroll loop runs out and falls back to a non-canonical 2-path snapshot. Acceptable for now; if it's perceptibly bad, raise the knobs above or relax `minPathLength` for 2-path.
- **Animate Rotations now defaults ON** (`ANIMATE_ROTATIONS = true` in render.js, `<input checked>` in index.html). Was off when first added.

## 2026-04-28 — Leaderboard / time-attack design (planned, not implemented)

- **Shape**: endless ladder, score = level reached, tiebreaker = cumulative solve time (lower is better). Starts at 4×4, grids grow each level. Fixed per-level timer (~100 sec). Game over when timer hits 0 mid-puzzle.
- **Banked time carryover**: unused time on a level rolls into the next level's clock. Creates strategic depth (race early, cushion for late). Apply a **soft cap** at ~2× per-level base so stockpiling doesn't trivialize mid-game. Without a cap, skilled players coast.
- **Three leaderboards by path count (1/2/3)** = three difficulty tiers. Path count is the genuinely-orthogonal difficulty axis (different cognitive style). Twin density still scales with grid size for visual variety, but is NOT a difficulty axis (we established twins don't shrink the search space — partner is filler, irrelevant rotation). Don't market "more twins = harder."
- **Hints in ladder mode cost banked time** (~15 sec each). Forces strategic spend; at the bank cap, hints are "free" (would lose overflow anyway) but deep in a hard level they're a real sacrifice.
- **Anti-cheat**: time-based JS leaderboards are trivially cheatable (pause timer in devtools, edit score). Design the submission payload NOW to include the seed + rotation sequence so server-side replay validation can be added later without breaking old scores. Don't have to build validation day-one but don't lock yourself out of it.

Lookahead gives enough lead time even at 14×14+; hurry is the only path that can ship a sub-canonical puzzle, and only when player actually caught up. ## 2026-04-25 — DPR fix: render in device pixels

- **The persistent "thin lines at tile boundaries inside path channels" bug ate ~10 iterations.** Root cause: Canvas anti-aliasing on non-integer DPR displays (Windows scaling 1.25/1.5). With the usual `ctx.scale(dpr)` setup, integer CSS coords land on FRACTIONAL device pixels — adjacent tiles' fillRect/stroke edges had AA-mismatched pixels at every shared boundary, showing as faint cross-channel lines. **Fix:** compute everything in device pixels (`canvas.width = grid + 2*pad` directly, `ctx.setTransform(1,0,0,1,0,0)` — no DPR scaling), force `cellSize` even, `cellAt` converts incoming CSS pointer coords to device pixels. Earlier attempts (per-cell gridline skip, channel extension by bevel-thickness, removing L/R bevel contrast, fillRect-instead-of-stroke for straights) ALL FAILED because they fought the symptom on the CSS side; only device-pixel rendering eliminates it.
- **Game now framed as a "circuit"** — entry/exit notches connect via an external connector around the grid perimeter, drawn as ONE polyline through `drawCircuitOutline` so every corner is a smooth `lineJoin='round'` bend (separate strokes had visible butt-cap seams). Lit palette is `LIT_GREEN` while in progress, flips to `LIT_GOLD` the moment `Maze.won` becomes true (single `litPalette()` drives every lit element). User mused about renaming the game to something circuit-related but didn't commit.
- **Twin locking** added — `TWIN_PAIR_COUNT` tile pairs (one path-tile + one filler each) rotate together via `_twin = { partner, color }` tags. Cross tiles deliberately excluded (4-rotation-symmetric → coupling would be invisible). Per-pair pastel palette derived programmatically from a base hex via `paletteFromBase` (additive lighten for top, multiplicative darken for bot/right). Hint-locked twins lock their partner too (with the same rotation delta) so they can't desync.
- **Cheat → Hint** rename (i18n key, button id, JS function). Hint-locked path tiles now also light their solution lane gold *before* the connecting chain reaches them — red bevel = locked, gold groove = confirmed-correct.
- **Difficulty thresholds scale with SIZE** in `maze.js`: `MIN_PATH_LENGTH = round(SIZE * 2.25)`, `MIN_PUZZLE_LENGTH = round(SIZE * 1.75)`, `MIN_SHORTCUT_TWISTS = round(SIZE * 1.25)`, `MAX_DFS_STEPS = SIZE² * 125`, `TWIN_PAIR_COUNT = max(1, SIZE−5)`.
